# Handoff — ssh-ci-wire (phase 24)

- **Teammate:** ci
- **Date:** 2026-06-10T00:10:00Z
- **Gate:** `ssh-ci-wire` — wire the snapdir-ssh-store T2 loopback sshd suite into CI so it can never rot into all-skips.

## Summary

No new CI job (per the Phase 7 plan): T1+T2 ride the existing `cargo test
--workspace` matrix. Two surfaces changed:

1. **`.github/workflows/ci.yaml`**
   - **test job (matrix ubuntu+macos × 1.91.1/stable/beta):** added a
     Linux-only step (`if: runner.os == 'Linux'`) before Build/Test that runs
     `sudo apt-get update && sudo apt-get install -y --no-install-recommends
     openssh-server` (ubuntu images ship the ssh client + ssh-keygen but not
     `sshd`; macOS ships `/usr/sbin/sshd` natively, no step needed). Added
     `SNAPDIR_SSH_TEST_REQUIRE: "1"` as step-level `env` on the
     "Test (workspace, locked)" step, so the loopback suite panics instead of
     eprintln-skipping.
   - **coverage job:** `cargo llvm-cov` RUNS the workspace tests (including
     `tests/loopback_sshd.rs`) on ubuntu, so it got the same
     `openssh-server` install step (no `if:` guard — the job is ubuntu-only,
     matching the valgrind/musl-tools step style) and
     `SNAPDIR_SSH_TEST_REQUIRE: "1"` on the llvm-cov step. Rationale: letting
     it skip there would silently drop the real-sshd code paths from the
     75%-floor coverage measurement.

2. **`utils/ci/pre-push.sh` (local mirror):** `export
   SNAPDIR_SSH_TEST_REQUIRE=1` in the setup section (next to the other
   mirror constants), with a comment. It applies to the test group (group 3,
   incl. the MSRV leg) AND coverage (group 6) — exactly mirroring ci.yaml.
   Machine profile warrants it: this is a macOS dev machine and macOS always
   ships `/usr/sbin/sshd`; on a Linux dev box the panic message names the
   missing tool (`apt-get install openssh-server`). The hook entry point
   `utils/git-hooks/pre-push` is unchanged (it just execs pre-push.sh --fast).
   shellcheck clean on both.

## Per-job decisions (every ci.yaml job audited)

| Job | Runs the loopback_sshd test binary? | Decision |
|---|---|---|
| test (matrix) | YES (`cargo test --workspace`) | install openssh-server (Linux-only step) + `SNAPDIR_SSH_TEST_REQUIRE=1` on the test step |
| coverage | YES (`cargo llvm-cov` runs tests) | install openssh-server + `SNAPDIR_SSH_TEST_REQUIRE=1` (do NOT let it skip — ssh-store paths must count toward the 75% floor) |
| musl | NO — verified build-only (`cargo build --target x86_64-unknown-linux-musl`, debug+release) | no change |
| doctests | NO — `cargo test --doc` never runs integration tests | no change |
| bench-iai | NO — `cargo bench -p snapdir-benches --bench iai_hot` only | no change |
| lint / deny | NO — no test execution | no change |

The bench-compile step inside the test job (`cargo bench --no-run`) compiles
only; the job-level env addition is scoped to the test step so it cannot leak
surprises elsewhere.
