# Handoff: cli-plumbing (phase 24)

## Summary

Hidden SNAPPACK plumbing landed in `crates/snapdir-cli/` — thin parse/resolve/render
glue over the freshly landed `snapdir_stores::pack` + `StreamStore::objects_needed`
(18f76d3); zero wire logic reimplemented in the CLI.

1. **`snapdir version --capabilities`** — hidden `#[arg(hide = true)]` bool on the
   existing `Version` variant. Emits exactly one line:
   `snapdir <CARGO_PKG_VERSION> wire=<WIRE_VERSION> caps=<WIRE_CAPS joined with ,>`
   (today: `snapdir 1.4.0 wire=1 caps=objects-needed,send-pack,receive-pack`),
   both baked from the lib constants — never semver. Plain `snapdir version`
   stays byte-identical (test-pinned).
2. **`snapdir objects-needed --store <url>`** (hidden subcommand) — reads stdin to
   EOF, validates EVERY non-empty line against `^[0-9a-f]{64}$` BEFORE the store is
   even resolved (fail closed: malformed request → exit≠0, NOTHING on stdout; empty
   input → exit 0, nothing printed), dedupes preserving first-occurrence order (the
   lib documents dedup as caller's job), resolves via the existing
   `stream_store_for_adapter` (External-rejection message kept verbatim), calls
   `StreamStore::objects_needed`, prints the absent subset one per line.
3. **`snapdir send-pack --store <url> --ids <FILE|-> [--manifest-id <id>]`**
   (hidden) — same strict validation + dedup on the id list (file or stdin),
   hex64-validates `--manifest-id`, then `pack::write_pack(store, ids, manifest_id,
   stdout.lock())`. Raw pack bytes are the entire stdout; the one summary line goes
   to stderr (suppressed by `--quiet`). Missing object → write_pack aborts before
   `end` → exit≠0 and the partial stream fails any consumer.
4. **`snapdir receive-pack --store <url> [--require-manifest <id>]`** (hidden) —
   `--require-manifest` hex64-validated up front; `Adapter::File` (the hot ssh
   path) goes through the streaming O(1)-memory `FileSink`, every other
   StreamStore through the generic `StreamSink`; `pack::read_pack` does all
   verification. A tiny `RecordingSink` PackSink decorator (pure delegation)
   records WHICH manifest id committed, because the read report only says
   *whether* one did and a pre-existing manifest in the store could otherwise mask
   a wrong-id stream. Mismatch or no-manifest-when-required → exit≠0 (after the
   read, per spec). Objects-written/skipped summary on stderr, stdout silent.

Exit codes ride the crate's existing convention (`main.rs`: Err → `eprintln` +
`ExitCode::FAILURE`).

CLI-compat freeze respected: the new subcommands are `#[command(hide = true)]`
(precedent: `Completions`/`Man`), the flag is `#[arg(hide = true)]` — all 16 trycmd
help/version snapshots pass byte-stable, untouched.

Gate tests in `crates/snapdir-cli/tests/plumbing.rs` (12 tests, real binary via
`env!("CARGO_BIN_EXE_snapdir")`, temp `file://` stores; snapshot fixtures pushed
with the binary itself, raw object fixtures via the snapdir-stores `FileStore`
dep, matching the e2e fixture style):
- capabilities line pinned BOTH to the literal `wire=1 caps=…` string and
  re-derived from `WIRE_VERSION`/`WIRE_CAPS`; plain `version` unchanged.
- objects-needed: seeded subset + full ordered dup-bearing stdin → stdout is the
  EXACT complement in first-occurrence order; uppercase/63-char/non-hex line →
  exit≠0 + empty stdout; empty stdin → exit 0 + empty stdout.
- pack round-trip: `send-pack --ids - --manifest-id <id>` connected to
  `receive-pack --require-manifest <id>` through a REAL OS pipe
  (`Stdio::from(child.stdout)`) → B holds the byte-equal manifest + objects at the
  identical sharded paths; receive-pack stdout empty.
- security: hand-crafted stream claiming X over bytes hashing Y → exit≠0, nothing
  at X's sharded path, store completely empty (no temp litter); `../`-flavored /
  non-hex headers rejected, nothing filed; truncated stream (cut before `end`,
  after complete records) → exit≠0, verified objects ARE filed, manifest NOT
  committed.
- idempotency: after the truncation, the FULL pack into the same store succeeds
  and commits the byte-equal manifest (completes the interrupted push).
- send-pack with an absent id → exit≠0 and emitted bytes do NOT end with `end\n`
  (covers the `--ids <FILE>` branch); malformed id → exit≠0 with zero pack bytes.
- require-manifest mismatch (stream carries M, flag says other) → exit≠0.

## Reuse check

- All wire logic is `snapdir_stores::pack` (`write_pack`/`read_pack`/`FileSink`/
  `StreamSink`/`is_hex64`/`WIRE_VERSION`/`WIRE_CAPS`) + the defaulted
  `StreamStore::objects_needed` — nothing re-parsed/re-framed in the CLI.
- Store resolution reuses the existing `stream_store_for_adapter` (sync's router,
  External error message intact) via a small `resolve_stream_store` wrapper
  mirroring `resolve_store`; per-backend config via the existing
  `transfer_config_for(adapter.name())`.
- Single `read_checksum_lines` + `dedupe_preserving_order` pair shared by
  objects-needed and send-pack.
- The only new abstraction is `RecordingSink` (delegating PackSink decorator) —
  needed because `PackReadReport.manifest_committed` is a bool and
  `--require-manifest` must compare the actual committed id.
