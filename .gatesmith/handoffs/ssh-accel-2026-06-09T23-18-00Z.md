# Handoff — gate `ssh-accel` (phase 24, stores lane)

## Summary

Runtime-negotiated SNAPPACK acceleration in the emitted `ssh://` scripts (sftp untouched), all in
`crates/snapdir-ssh-store/`:

- **Combined probe, ONE round trip (push)**: the old bare manifest probe is replaced by
  `if test -f '<man>'; then echo manifest=1; else echo manifest=0; fi; command -v snapdir
  >/dev/null 2>&1 && snapdir version --capabilities || echo 'caps none'` into
  `$snapdir_tmp/probe`. The remote command always exits 0, so ANY nonzero ssh exit is
  connectivity, surfaced with the real exit code (never not-found). Fetch gets a caps-only probe,
  and ONLY when there is something to fetch (empty needed set + no SENDALL → zero round trips).
- **Push dispatch**: `manifest=1` → exact no-op wording + exit 0; `SNAPDIR_SSH_NO_ACCEL=1` (or no
  usable local snapdir — graceful degradation) → `_snapdir_dumb_push`; caps OK
  (`objects-needed` + `receive-pack`) → `_snapdir_accel_push`; `SNAPDIR_SSH_FORCE_ACCEL=1`
  without caps → designed stderr error naming the host, required `wire=1` + caps, the verbatim
  probe output (`cat "$snapdir_tmp/probe"`), and both remedies; exit 1. Else dumb.
- **Caps check** (`_snapdir_caps_ok`, bash-3.2/POSIX): first probe line starting `snapdir `,
  exact ` wire=1 ` token match (baked emit-time literal), required caps matched word-bounded in
  the comma-wrapped `caps=` list.
- **`_snapdir_accel_push`**: baked want heredoc (deduped F-checksums) → remote
  `snapdir objects-needed --store 'file://<base>'` (failure → `_snapdir_dumb_push`, nothing
  written, idempotent) → `"$snapdir_local" send-pack --store 'file://<staging-ABS>' --ids
  "$snapdir_tmp/need" --manifest-id '<id>' | _snapdir_ssh 'snapdir receive-pack … --require-manifest
  '<id>'`. Manifest rides the pack LAST; remote commits only after the verified `end` trailer. An
  EMPTY missing list still streams the manifest-only pack (interrupted-push completion —
  verified live: the CLI's `--ids <empty file>` produces a manifest-only pack). Stream failure →
  exit nonzero with "retrying the push resumes incrementally"; NO silent dumb fallback mid-stream.
- **`_snapdir_accel_fetch`**: BOTH id lists baked (`$snapdir_tmp/ids` = emit-time cache diff,
  `$snapdir_tmp/ids_all` = full F-checksum list), picked at runtime via
  `SNAPDIR_SSH_PULL_SENDALL=1`; `_snapdir_ssh 'snapdir send-pack … --ids -' <"$snapdir_ids" |
  "$snapdir_local" receive-pack --store 'file://<cache-ABS>'` — the remote stream is untrusted,
  the LOCAL receive-pack hash-verifies every record. Same no-silent-fallback stream policy.
- **Local binary resolution**: `snapdir_local="${SNAPDIR_SSH_LOCAL_SNAPDIR:-snapdir}"` at script
  runtime; the env override is documented as test/debug plumbing; a missing local binary flips
  `snapdir_local_ok=0` → graceful dumb fallback (asserted in the text tests).
- **Staging/cache paths** made absolute defensively at emit time (`absolute_dir`) before being
  handed to `--store file://`.
- **Fixture**: `fake-ssh` gained `FAKE_SSH_REMOTE_PATH` (a dir prepended to PATH before the
  remote command runs). All existing knobs untouched; fake_sftp + fake_ssh_roundtrip suites green.
- **Hermeticity hardening**: `fake_ssh_roundtrip.rs` (the dumb-contract suite) now pins
  `SNAPDIR_SSH_NO_ACCEL=1` and scrubs leakable knobs, so a wire-capable `snapdir` on a developer's
  PATH can never flip those tests onto the accel path; its three emitted-text assertions were
  updated for the new dispatch tail (dumb bodies still asserted present and invoked).

## Reuse check

- **Seam reused exactly as designed**: the dumb bodies (`_snapdir_dumb_push`/`_snapdir_dumb_fetch`
  shell functions, landed @1762463) are untouched; the accel gate only swapped the probe and added
  prelude + accel functions + dispatch around them. Both paths embedded in every emitted script.
- **Wire literal from `pack::WIRE_VERSION`**: the shipped lib depends only on `snapdir-core` (plan
  decision 4), so `ssh_engine::WIRE_VERSION = 1` is a local const baked into the emitted ` wire=1 `
  token, pinned by unit test `wire_version_matches_snapdir_stores` to
  `snapdir_stores::WIRE_VERSION` (dev-dep), and `required_caps_are_advertised_by_the_cli_constants`
  pins PUSH/FETCH caps to `snapdir_stores::WIRE_CAPS`. Never parsed from the semver at runtime.
- **CLI plumbing reused as-is** (@187b53d): `version --capabilities`, `objects-needed`,
  `send-pack --ids <FILE|->`, `receive-pack --require-manifest` — no CLI changes; the empty
  `--ids` file → manifest-only pack semantics were verified live by the interrupted-push test.
  Manifest byte canonicalization (`to_string()` + `\n`, matching `file_store::write_manifest` and
  `pack.rs`) is honored by the test harness's staged manifests, so the oracle compares true bytes.
- **Fallback policy per plan**: probe/diff failure → dumb (nothing written, idempotent); stream
  failure → nonzero + incremental-retry message, never a silent dumb retry; FORCE_ACCEL →
  designed error; NO_ACCEL → dumb even with full caps (sentinel-fake proven);
  connectivity NEVER maps to not-found/no-caps (probe guard surfaces the real ssh exit).
- **Binary location note (per spawn brief)**: `CARGO_BIN_EXE_snapdir` is unavailable here, so
  accel.rs locates the real binary as a sibling target artifact
  (`current_exe()/../../snapdir`, fallback `CARGO_MANIFEST_DIR/../../target/<profile>/snapdir`)
  and eprintln-skips ONLY when truly absent. CI runs `cargo test --workspace` where snapdir-cli
  builds first, so the accel tests always run in CI; adding snapdir-cli as a dev-dep was
  (correctly) rejected as too heavy.
