# Handoff: gate `sftp-engine` (phase 24) — stores lane

## Summary

Implemented the `sftp://` transport engine (`src/sftp_engine.rs`): pure SFTP
protocol, no remote shell, no tar, no acceleration — every operation is an
`sftp -b` batchfile run over the shared ControlMaster via the scaffold's
`_snapdir_sftp` wrapper, so it works against `ForceCommand internal-sftp`
chroots. All three subcommands wired into the lib.rs dispatch for
`Engine::Sftp` (`Engine::Ssh` stays fail-closed for the next gate); the
binary now reads the fetch manifest from stdin at emit time.

- **Probe** (shared by get-manifest/push): single `ls <manifest>` batch; on
  failure a `pwd` liveness batch over the live master disambiguates missing
  vs unreachable — connectivity never maps to not-found and never triggers a
  silent re-push (probe stderr is surfaced, exit 1).
- **get-manifest**: probe → exact `ID '<id>' not found on --store
  '<store>'.` on stderr + exit 1, or `get` into `$snapdir_tmp` with sftp
  chatter redirected away from stdout, then `cat` (stdout carries only
  manifest bytes).
- **push**: staged manifest read at emit time (clear error if absent);
  probe short-circuit with exact `Manifest already exists on store.`; ONE
  tolerated `-ls` batch probes every candidate object; the script parses its
  stdout (drops `sftp> ` echo lines; a line exactly matching a probed path =
  present; any unrecognized line degrades to upload-all); missing objects are
  distributed round-robin into JOBS parallel chunk batches (per chunk:
  `sort -u`-deduped `-mkdir` ancestor chains first, then per-object `put` to
  `.tmp.<emit-nonce>` → `-rm` → `rename` → `chmod 600`), backgrounded with
  explicit per-pid `wait` + status collection (nothing left for the
  orchestrator's trailing bare `wait`); manifest LAST in its own final batch
  with the same tmp/rename/chmod discipline.
- **fetch**: emit-time dedupe + cache-dir filter; `ltmp=$(mktemp -d
  <cache>/.snapdir-incoming.XXXXXX)` (cleanup-trap extended so an abort never
  strands it); chunked tolerated `-get` batches into flat checksum names,
  backgrounded, waited per-pid with exits IGNORED; epilogue loop moves
  present objects into the sharded cache layout and prints exact
  `ERROR: missing object <checksum>` per absent one, removes ltmp, exits
  nonzero on any missing.
- Injection defense: ids and checksums validated `^[0-9a-f]{64}$` at emit
  time; local dirs reject control chars (cache-dir additionally `"`/`\`,
  because it is the one value spliced into batch lines at runtime via
  `printf` between emit-quoted tokens); all remote paths sftp-quoted and all
  shell embeddings sh-quoted at emit time.

Fixture `tests/fixtures/fake-sftp` (bash-3.2-clean, executable): parses the
exact `sftp <-o flags...> -b <file> -- <host>` CLI shape, interprets exactly
the emitted verbs (`ls get put rm rename mkdir chmod pwd`, with `-`
tolerance and unprefixed-failure batch abort), maps the host's absolute
paths under `$FAKE_REMOTE_ROOT`, echoes `sftp> <cmd>` on stdout like real
sftp (so the `-ls` listing parse is honestly exercised), uses STRICT rename
(fails if target exists — harder than posix-rename, proving the `-rm`
discipline), single-level mkdir (fails if exists — proving `-mkdir`
tolerance), and honors `FAKE_SFTP_FAIL_VERB`/`FAKE_SFTP_FAIL_AFTER`
(per-process counting; an injected put failure leaves a PARTIAL file at the
destination) and `FAKE_SFTP_UNREACHABLE=1` (exit 255 before the batch).

Gate tests `tests/fake_sftp_roundtrip.rs` (10 tests, hermetic, driven
through `snapdir_stores::ExternalStore::with_binary(env!("CARGO_BIN_EXE_snapdir-sftp-store"))`,
per-test bindir with the fixture installed as `sftp` prepended to PATH,
env-touching tests serialized on an EnvGuard mutex): parity round-trip
(remote sharded layout + chmod 600 + byte-equal get-manifest + cache-layout
fetch + no incoming-dir residue), not-found → `StoreError::ManifestNotFound`,
unreachable → `StoreError::Backend` (NOT not-found), idempotent second push
(deleted remote object NOT re-copied), atomicity (JOBS=1 + fail 2nd put →
some objects, NO manifest, no non-tmp partials at final paths; injection
cleared → retry completes), fetch-missing-object (exact
`ERROR: missing object <sum>` in the Backend message), plus 4 pure
emitted-text tests (manifest-last ordering, put-to-tmp + `-rm` + rename +
chmod discipline for objects AND manifest, no unprefixed `ls` of object
paths, exact wordings, stdout purity, tolerated `-get` + ignored chunk
exits + per-pid wait, emit-time cache filtering).

## Reuse check

- **Skeleton + quoting fully reused**: every script starts with
  `script::skeleton` (ControlMaster mux, 0700 tmp dir, cleanup traps,
  ordered security floor); all batch/script text goes through
  `script::{sh_quote, sftp_quote, heredoc}`; sharding exclusively via
  `snapdir_core::store::{object_path, manifest_path}` through the existing
  `script::remote_{object,manifest}_path` helpers (the bash runtime never
  recomputes shards — per-object batch text is fully baked at emit time and
  only *selected/distributed* at runtime).
- **Exact wordings**: `ID '<id>' not found on --store '<store>'.`,
  `ERROR: missing object <checksum>`, `Manifest already exists on store.` —
  all asserted byte-exact in tests, all flowing through the real shim
  mapping (`ManifestNotFound` / `Backend` / no-op).
- **`-ls` parse degradation is honest**: the fixture echoes `sftp> <cmd>`
  lines on stdout exactly like real sftp, so the script's
  drop-echo-then-exact-match parse runs against realistic output in every
  push test; any non-candidate listing line flips `snapdir_upload_all=1`
  (correctness over bandwidth, never wrong).
- **Divergences / decisions (documented)**:
  - **No `ssh` stub in fixtures** — decided per the task's "test and
    decide": the skeleton's cleanup (`command ssh … -O exit … 2>/dev/null ||
    true`) hits the *real* ssh (system PATH stays appended after the
    fixture bindir), which fails instantly on the nonexistent ControlPath
    socket and is swallowed by `|| true`. Verified implicitly by all 10
    tests passing with the cleanup trap firing; noted in the test module
    docs.
  - **bash-3.2 proof is live, not just textual**: the test harness shadows
    `bash` with `/bin/bash` (3.2.57 on this macOS host) in the per-test
    bindir, so the shim's eval shell runs every emitted script — and the
    fixture — under bash 3.2 on every test run.
  - Ids and manifest checksums are rejected unless `^[0-9a-f]{64}$` at emit
    time (stricter than the maximally-tolerant mock; consistent with the
    args.rs reject-with-clear-error philosophy — they are embedded in
    emitted text, the charset is the injection defense).
  - `rename` is emitted after a tolerated `-rm` so it works under strict
    SSH_FXP_RENAME semantics too (no reliance on posix-rename@openssh.com
    being offered); the fixture implements the STRICT semantics to keep the
    discipline honest.
  - `ssh -V` floor (`version::detect_openssh_floor`) is deliberately NOT yet
    called at dispatch — not in this gate's task list; flag it for wiring
    when the runtime engines meet real ssh (loopback-sshd phase at the
    latest) so emission fails closed on pre-8.5 clients.
  - Fault-injection counters in fake-sftp are per-process (per sftp
    invocation), documented in the fixture header; the atomicity test pins
    `SNAPDIR_SFTP_STORE_JOBS=1` for a deterministic Nth-put failure.
